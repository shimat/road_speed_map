# 道路最高速度マップ PoC

OpenStreetMapの道路網を、最高速度とその根拠・確度ごとに色分けするStreamlitアプリです。
地図上の道路をクリックし、現地確認や写真などを根拠に手動補正できます。

描画モードは3種類あります。既定の「データのみ」はJARTIC指定速度とOSMに数値で記録された
`maxspeed` だけを表示します。「知見を追加」は速度標識の補正と、人間が確認した道路構造を
上乗せします。
「推定候補をレビュー」は、さらに道路構造・道路種別からの法定速度推定を表示します。
推定候補は細い半透明線、原典値と手動確認値は太い不透明線で描き分けます。

札幌市周辺では「高速編集地図（試作）」を利用できます。道路クリックだけではStreamlitを
再実行せず、地図上のポップアップで速度標識または道路構造を入力します。「保存して反映」
または削除を押したときにだけPythonへ通知し、補正DBと地図を更新します。試作版をOFFにするか、
JARTIC配布元の検証線を表示すると従来のPyDeck地図へ戻ります。

> このアプリの法定速度はOSM属性からの推定を含みます。実際の運転では現地の標識・道路標示に従ってください。

## 現在のデータ優先順位

1. 画面から登録した速度標識の補正
2. JARTIC交通規制情報の指定速度（OSM道路へ位置・方向で自動対応）
3. OpenStreetMapの数値 `maxspeed`
4. 人間が確認した中央線・車両通行帯・上下線分離などから算出した法定速度候補
5. `lanes`、`lane_markings`、`divider`、道路種別などから推定した法定速度
6. 判断できない場合は「不明」

JARTIC配布元の規制線・区域は、検証用表示をONにすると地図上でホバー・クリックできます。
この表示をOFFにしても、OSM道路へ自動対応済みのJARTIC速度判定は残ります。対応処理は
15 m以内・方向差25度以内というヒューリスティックで、確度を「中」として表示します。
交差点や並行道路では誤対応の可能性があり、方向別・時間帯別規制の評価は今後の課題です。
黄色は50 km/hを表します。原典線が道路クリックを覆う場合は、サイドバーで原典線だけを
一時的に非表示にしても、OSM道路への自動対応結果は維持されます。

法定30km/hは、OSMの `lane_markings=no`、1車線、または `residential`、`service`、
`living_street`、`unclassified` といった生活道路系の道路種別から推定します。道路種別だけの
場合は中央線等が未確認なので確度を「低」とし、原典値とは見た目を分けます。推定線をクリックし、
速度標識を確認した場合は速度を直接補正できます。標識が見当たらない場合は、中央線、
車両通行帯、上下線分離、またはそれらがないことを観測事実として保存します。アプリが
30または60km/hの法定速度候補を算出し、指定速度の原典値がある場合はそちらを優先します。

## 起動

Python 3.11以降を使用します。

```powershell
uv sync
uv run streamlit run app.py
```

`uv`を使わない場合：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
streamlit run app.py
```

表示範囲は「札幌市周辺」「旭川市周辺」「函館市周辺」の3地域です。札幌市周辺は
札幌、小樽（忍路まで）、江別、恵庭、千歳（新千歳空港まで）、石狩南部を含みます。いずれも画面内でOverpass APIを
呼ばず、最初に次の前処理を1回実行します。

```powershell
uv run python scripts/prepare_regions.py
```

Geofabrikの北海道PBFを `data/source/` に1回ダウンロードし、各範囲の道路を抽出して、
JARTIC対応済みParquetを `data/processed/` に生成します。PBFと地域別の道路抽出結果は
再利用されるため、通常の再実行ではJARTIC対応と最終Parquetだけを更新します。
1地域だけ生成する場合は `--region "旭川市周辺"` のように指定できます。
OSM原本も更新する場合は次を使います。

```powershell
uv run python scripts/prepare_regions.py --refresh-pbf
```

JARTIC原本も更新する場合は `--refresh-jartic` を併用します。

各地域のエッジは、表示時に同一判定の連続区間へ結合し、座標を簡略化してブラウザー転送量を
抑えます。元エッジとの対応表はサーバー側に保持するため、結合区間をクリックした手動補正は
対象となる元セグメントへ一括保存されます。

速度標識の補正と道路構造の観測は `data/overrides.sqlite3` に別テーブルで保存します。
このファイルはGit管理対象外です。サイドバーからそれぞれCSVとして出力できます。

## テスト

コア処理のテストを実行できます。

```powershell
python -m unittest discover -s tests -v
```

## PoCの意図とスケール方針

地域単位なら、Parquetの事前生成と連続区間の結合によりStreamlit + PyDeckでもPoCとして
扱えます。ただし、全国へ拡大するとPythonからブラウザーへ道路をJSON転送する方式が
ボトルネックになります。

その場合も手動補正DBと速度判定処理は維持し、配信用データをGeoParquet/PostGISからMapbox Vector Tileへ変換し、MapLibre GL JSで表示する構成へ移行できます。Blazorを採用する場合も、MapLibre等のWebGL地図をJS interopで利用し、ベクトルタイルを配信する構成が現実的です。
